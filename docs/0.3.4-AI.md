# 0.3.4 · Conexión inicial del asistente

Entrada: icono de chat de la barra superior → ajustes del chat → proveedor, modelo y clave → Guardar proveedor → Probar conexión o enviar un mensaje.

Proveedores configurables: OpenCode Go, OpenCode Zen, OpenAI, Claude/Anthropic, Google Gemini, OpenRouter y API personalizada HTTPS. Adaptadores de texto: Chat Completions, Responses, Anthropic Messages y Gemini generateContent. El modelo se introduce explícitamente; no se fija una opción de pago ni se cambia de proveedor automáticamente. OpenCode usa formatos distintos según el modelo; se sugiere el protocolo por familia y se permite corregirlo en Configuración de la API.

La clave y la configuración se guardan mediante flutter_secure_storage 9.2.4, con almacenamiento protegido de la plataforma. No están en Git, la APK ni las copias de entrenamiento. No se imprimen los cuerpos de errores remotos, que podrían incluir secretos. Solo se aceptan endpoints HTTPS sin credenciales ni parámetros en la URL; no se siguen redirecciones al enviar la clave. El usuario introduce sus claves en el móvil. Cambiar de proveedor vacía el campo de clave en el formulario; la nueva selección solo se activa al guardar.

## OpenCode Go

El usuario confirmó que tiene Go y sus claves API. El preset usa https://opencode.ai/zen/go/v1. Se envía User-Agent GymIA/0.3.4 y x-opencode-session estable por conversación, sin hacerse pasar por un agente de programación. La documentación actual describe Go como servicio para tráfico de agentes de programación; que exista una clave no verifica compatibilidad con solicitudes de gimnasio. Pendiente comprobar con el proveedor y mediante una petición real desde el teléfono. No se activa fallback a Zen ni se ocultan rechazos de acceso.

## Chat inicial y límites

El chat conserva hasta 80 mensajes localmente en almacenamiento protegido y envía hasta 20 mensajes recientes al proveedor. Incluye la sesión activa y hasta cinco sesiones completadas disponibles en SQLite como contexto. La pantalla explica que el proveedor recibe conversación/contexto al enviar. No accede aún al histórico remoto de ChatGPT ni a datos de Sheets que no se hayan importado.

La respuesta se presenta como conversación: esta entrega no tiene herramientas de mutación, parser de series, voz, fotos, búsqueda web ni escritura Sheets. El prompt especifica ese límite y prohíbe afirmar registros o guardados ejecutados. Las operaciones de entrenamiento siguen en los controles existentes. Este es el primer paso de conexión dentro de la entrega del asistente, no su aceptación completa.

La conversación se conserva al reabrir el chat, pero todavía no forma parte de las copias JSON de entrenamiento; la clave tampoco debe incluirse en ellas. Falta migrar el contexto de conversación a la persistencia operativa definitiva y añadir gestión de conversaciones. Sin red pueden consultarse mensajes ya guardados, pero no generar respuestas del LLM.

## Validación

Pruebas sin llamadas a cuentas reales: endpoint y encabezados Go con sesión estable, separación system/mensajes, lectura de respuestas de los cuatro formatos, exclusión de bloques de razonamiento, URLs inválidas que no envían credenciales, errores sin filtrar secretos, configuración eliminable, clave excluida de backup, recuperación del chat y ausencia de mutaciones de entrenamientos. Las pruebas del almacén protegido usan la implementación simulada del plugin; no prueban Android Keystore en un teléfono.

APK release compilada. Pendiente prueba real del proveedor con clave del usuario en el móvil. No se han consumido sus créditos ni se han solicitado sus claves por este chat. iOS sigue sin validar.

Resultado local: 45 pruebas pasaron; después se añadió la normalización de nombres opencode-go/modelo y opencode/modelo y pasaron las 8 pruebas del adaptador (46 pruebas en total). flutter analyze sin incidencias. Aún no se ha validado la llamada real a Go ni el almacén nativo en el teléfono.
