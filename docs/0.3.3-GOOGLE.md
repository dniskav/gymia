# 0.3.3 · Autorización e importación desde Google Sheets

Flujo: Tus datos → Importar desde Google Sheets → elegir cuenta → autorización de lectura → buscar hoja → elegir pestaña → revisar columnas y datos → confirmar importación.

La cuenta se elige con AccountPicker de Google Play Services. AuthorizationClient solicita spreadsheets.readonly y drive.metadata.readonly. Drive API lista hojas nativas por nombre con paginación. Sheets API obtiene pestañas y lee filas como valores formateados para conservar fechas y decimales según la hoja. El mismo importador existente prepara la revisión y la deduplicación. No escribe en Google Sheets. Las credenciales temporales se conservan en memoria de Android, no se envían a Dart, no se registran y no se almacenan en las copias de seguridad.

El registro de entrenamiento sigue disponible offline. Se añade permiso de Internet para las llamadas HTTPS directas a Google. Las consultas se realizan fuera del hilo principal, con timeouts y límite de respuesta de 20 MB. Los errores de autorización, permisos, hoja desaparecida y cuota muestran mensajes específicos. Cancelar la autorización o la pestaña no importa datos.

## Configuración externa necesaria

La app no puede registrar por sí misma su cliente OAuth. Configurar un proyecto de Google Cloud:

1. Activar Google Drive API y Google Sheets API.
2. Configurar Google Auth Platform para público externo en Testing y añadir el correo del teléfono como usuario de prueba.
3. Declarar https://www.googleapis.com/auth/spreadsheets.readonly y https://www.googleapis.com/auth/drive.metadata.readonly.
4. Registrar cliente Android para paquete com.gymia.app y SHA-1 47:5C:74:12:0F:97:B5:89:D8:2A:5F:05:29:2B:9E:46:3B:36:85:C1.

AuthorizationClient para acceso directo en el dispositivo reconoce el cliente por paquete y firma. Este flujo no intercambia códigos con un backend ni incorpora un secreto de cliente en la APK. La versión debug usa paquete/firma diferentes y requiere otro registro si se quiere probar contra Google.

## Verificación y límites

Se compila la APK release con la firma anterior. Las pruebas de Flutter simulan la respuesta del canal nativo para validar orden de autorización/lectura, selección de pestaña, cancelación, búsqueda y paginación. No validan una autorización Google real. Pendiente completar el registro en Google Cloud y probar el consentimiento y la lectura con la cuenta del usuario.

Resultado local: 35 pruebas pasan. El APK mantiene com.gymia.app, versión 0.3.3 (6), minSdk 23 y el mismo certificado SHA-256 8ec5268d28e98116155e2ed660359f7ddb1fa0d41568146759c28ac01a32aac6. El usuario está comenzando la configuración de Cloud; no se ha confirmado aún el registro OAuth.

La hoja real aún no se ha inspeccionado. El importador espera encabezados y una fila por serie; una hoja organizada en bloques requiere adaptar esa interpretación. Mantener Sprint 3 pendiente hasta comprobar el histórico real.

Dependencia Android fijada en play-services-auth 21.5.0 para conservar minSdk 23; 22.0.0 requiere minSdk 24 y falló al combinar manifiestos.
