# 0.3.21 · Continuar con ChatGPT en Android

## Uso

En Proveedor de IA, elige **ChatGPT · usar mi plan** y pulsa **Continuar con
ChatGPT**. La autorización se abre en el navegador del sistema. La primera
conexión solicita identidad; después, **Autorizar uso de mi plan ChatGPT** pide
por separado los permisos de inferencia y renovación. Elige un modelo del
catálogo de esa cuenta y pulsa **Probar conexión · usa mi plan ChatGPT**. Esa
prueba realiza una inferencia y consume uso del plan si está autorizada.

Se conservan los proveedores con API key. No hay cambio automático de proveedor
ni de forma de pago al fallar ChatGPT. El enlace de Uso abre los ajustes oficiales
de ChatGPT; la desconexión intenta revocar y borra los tokens locales. Si no se
confirma la revocación remota, se indica expresamente.

Conectar ChatGPT no conecta Google ni fusiona perfiles/históricos. Cada registro
ChatGPT queda en el perfil GymIA donde se añadió. Cuenta y espacio se conservan
por identidad validada y client ID emitido, incluso si comparten email. Cambiar
el proveedor no borra automáticamente otras conexiones guardadas.

## Implementación

- Cliente público OSS, sin servidor, client secret ni API key del mantenedor.
- Registro inicial dinámico, client ID emitido reutilizado, host ID estable,
  navegador externo, PKCE S256, state, nonce y callback local de un solo uso.
- Listener exclusivo en `127.0.0.1` con puerto libre y ruta `/auth/callback`.
  Comprueba método, Host, estado, parámetros duplicados y retornos repetidos;
  limita espera y cierra el socket en éxito, cancelación o error. No escucha en
  la red local ni habilita HTTP general. Un proceso destruido requiere reintentar.
- OIDC: firma RS256 mediante JOSE y JWKS del emisor oficial, audiencia, emisor,
  caducidad, fecha de emisión, nonce y sujeto. Un token decodificado no basta.
- Registro protegido por FlutterSecureStorage/Android Keystore, separado del JSON
  de configuración/verificación del proveedor. No se exportan ni registran tokens.
  La app ya deshabilita copias Android de sus datos.
- Renovación serializada, sustitución conjunta de tokens rotados y un único
  reintento tras 401 HTTP previo al stream. Los fallos de streaming no se reenvían
  automáticamente. Errores terminales de refresh eliminan los tokens inutilizables.
- Desconectar invalida resultados en vuelo para impedir ejecutar acciones tardías.
  Conserva la correspondencia cuenta/client ID para una conexión posterior.
- Acceso OAuth restringido a `https://api.openai.com/v1`; no se admite cambiarlo
  por una URL personalizada. No usa cookies ni endpoints privados de ChatGPT.
- Catálogo específico por cuenta: array `models`, visibilidad `list`, `slug` y
  nombre visible. No se impone un modelo fijo ni se reutiliza el catálogo API key.
- Responses siempre con `stream:true`, `store:false`, contexto explícito e
  instrucciones compatibles, también en verificaciones y planificación de Sheets
  sin consumidor de texto parcial. Una respuesta truncada o fallida no es éxito.
- Mensajes específicos para no elegibilidad, límites, capacidad no admitida,
  permisos, revocación y fallos temporales. Los errores conservan estado HTTP,
  código, parámetro, forma de respuesta y request ID cuando están disponibles;
  los cuerpos de error no se muestran sin filtrar ni se guardan como logs.

## Validación y límites

Las pruebas unitarias cubren PKCE, callbacks falsos/repetidos, firma y claims,
identidad sustituida, permisos separados, aislamiento de perfiles y de registros
con el mismo email, renovación simultánea, reintento del intercambio,
timeout, cancelación, revocación, configuración sin tokens y Responses SSE real
contra un servidor de prueba, con y sin finalización. Las pruebas de widgets
comprueban ajustes, verificación, desconexión offline y proveedor API key anterior.

En Android se prueba el flujo completo con loopback real, firma criptográfica y
almacenamiento seguro reales, con transporte OpenAI controlado. También se abre
el navegador real hasta la página oficial de inicio de sesión y se vuelve a GymIA
al cancelar. No se introducen credenciales del usuario en esas pruebas.

**No se ha validado una concesión real ni inferencia con el plan de un usuario.**
Llegar a la página de login no prueba admisión, elegibilidad, consentimiento ni
consumo del plan. Falta completar ese recorrido con una cuenta elegible en un
móvil físico; no se promete acceso a todos los usuarios, espacios o modelos.
La integración sigue las limitaciones de preview: no añade transcripción, Files
upload ni herramientas alojadas no admitidas. El dictado Android existente
continúa enviando texto. Los adjuntos dependen del modelo autorizado.

## Resultado de esta entrega

- Flutter analyze: sin incidencias.
- Flutter test: 163 pruebas superadas.
- JVM de la app (`:app:testDebugUnitTest`): 9 pruebas sin fallos.
- Integración Android: 2 recorridos superados (OAuth controlado completo y
  apertura del navegador oficial/cancelación).
- APK release: `com.gymia.app`, versión 0.3.21, código 24, minSdk 23.
- Misma firma de actualización que 0.3.20; instalación `-r` y arranque correctos en el emulador.
- SHA-256 APK: `37621c60672cfd9ede30b65f086a747599b0682c26150a5f5b784e93d19141fb`.

La APK y las capturas QA se conservan en entregas locales, fuera del repositorio
público. La compilación no demuestra que OpenAI admita una cuenta concreta.

Nota de entorno de pruebas: la invocación global `testDebugUnitTest` también
intenta ejecutar suites de plugins. En este entorno esa invocación encontró una
incompatibilidad Jetifier/Byte Buddy en los tests del plugin lifecycle. La suite
nativa propia se comprueba con `:app:testDebugUnitTest`; no se cambiaron versiones
de plugins para sortear ese fallo externo. Las compilaciones debug/release y los
recorridos de la app Android finalizaron correctamente.
