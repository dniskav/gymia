# 0.3.6 · Historial con emojis y acentos

La captura del usuario muestra una primera respuesta con «👋», seguida de un error genérico al enviar el siguiente mensaje. El transporte utilizaba HttpClientRequest.write con Content-Type application/json sin charset. Dart selecciona Latin-1 en ese caso: los emojis del historial no son representables y los acentos no se transmiten como UTF-8.

El cuerpo se envía ahora como bytes UTF-8 explícitos, con charset=utf-8 en Content-Type. La configuración, proveedor e historial se conservan. Se distinguen interrupciones HTTP y respuestas JSON que no son objetos.

Prueba de regresión con un servidor HTTP local y el transporte real: petición con historial de dos turnos, acentos, emoji en la respuesta anterior y nuevo mensaje; se verifica el JSON recibido y una respuesta con emoji. No se usan claves reales ni se llama al proveedor. Queda pendiente confirmar la conversación en el móvil; esta corrección no permite atribuir cualquier otro error futuro a la misma causa.

Verificación: las 11 pruebas del cliente pasan; análisis sin incidencias; APK release 0.3.6+9 compilada y firmada con el certificado existente. SHA-256 registrado en releases/gymia-0.3.6.sha256.
