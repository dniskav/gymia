# 0.3.8 · Autorización Google sin cierre silencioso

El usuario informa que después de elegir Gmail se cierra el selector de hojas y que el selector de archivos de Drive no sirve para su hoja nativa. Había dos rutas diferentes: Google Sheets mediante autorización y API, y copias locales mediante ACTION_OPEN_DOCUMENT. La primera es la que debe usarse desde el chat para una hoja nativa.

La ruta anterior devolvía null ante cualquier resultado no OK de la actividad de Google y Flutter cerraba toda la pantalla. Esto ocultaba cancelaciones y errores del consentimiento. Ahora se parsea el resultado de autorización incluso si el código de actividad no es OK, preservando el ApiException/status de Google. Si no hay resultado se muestra una explicación de autorización incompleta. Flutter deja la pantalla abierta con opción de reintentar, incluso si un plugin devuelve null.

La conexión inicial usa directamente AuthorizationClient.authorize con los scopes de lectura. Google realiza selección de cuenta y consentimiento en un flujo, según su API oficial. AccountPicker queda solo para un cambio de cuenta solicitado explícitamente. Los errores 10 (configuración) y 16 (autorización incompleta/cancelada) se explican por separado. No se modifican scopes, firma, cliente OAuth externo ni los datos importados; la pantalla de autorización no abre Drive.

Prueba posterior: la cuenta conservada en el AVD completó la selección, el aviso de app en pruebas y el consentimiento de los dos permisos de lectura previstos. La app listó hojas reales y mostró Hoja de entrenamiento de ejemplo. El usuario facilitó el desbloqueo del emulador; no se guarda esa clave en el proyecto. El emulador no tiene un proveedor IA configurado: la copia se guarda correctamente, pero no se hizo una llamada real al LLM desde este dispositivo. Persistencia real verificada: tras forzar cierre de la APK y reabrirla, Hoja · Registro 2026 sigue presente; su diálogo conserva nombre, 111 filas y hora de lectura.

Actualizar hoja probado después de reabrir: AuthorizationClient renueva la autorización sin pedir otra selección de cuenta, Sheets vuelve a leer y guardar la pestaña; después se solicita configuración del proveedor IA, como corresponde al emulador sin clave. No se cambió el histórico de entrenamientos local ni la hoja de Google.

El usuario no podía escribir con el teclado del ordenador: hw.keyboard estaba desactivado en el AVD. Se habilitó y se reinició; hardware-qemu.ini confirma hw.keyboard=true. Se conserva el almacenamiento del emulador.

En la misma revisión externa, Google Sheets API estaba desactivada. Se habilitó en [proyecto privado omitido] y la página del servicio confirmó «Estado: Habilitada». La pantalla de acceso a datos contiene spreadsheets (lectura/escritura) y drive.metadata.readonly; la APK solicita spreadsheets.readonly y drive.metadata.readonly. El consentimiento real concedió estos dos permisos y la API de Drive respondió correctamente al listar las hojas.
